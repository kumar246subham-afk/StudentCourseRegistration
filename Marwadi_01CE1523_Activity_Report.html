1. Introduction

ASP.NET Core MVC is Microsoft's modern, open-source, cross-platform framework for building web applications using the Model-View-Controller (MVC) architectural design pattern. Unlike the legacy .NET Framework, ASP.NET Core is cloud-optimized, modular, and executes cross-platform on Windows, macOS, and Linux.

This self-learning activity applies ASP.NET Core MVC fundamentals to build an independent Student Course Registration System fulfilling all criteria set by the Department of Computer Engineering.

2. Learning Objectives

  • Understand the architecture of ASP.NET Core MVC and the request-response lifecycle.
  • Master the project directory structure (Program.cs, Models, Views, Controllers).
  • Differentiate between Model (State & Validation), View (Razor markup), and Controller (Dispatching).
  • Implement Razor Views, Tag Helpers (asp-for, asp-validation-for, asp-action, asp-controller), and layout pages.
  • Implement HTML form handling, model binding, and server-side validation using Data Annotations.
  • Enforce application flow via ModelState.IsValid and the POST-Redirect-GET (PRG) pattern.

3. ASP.NET Core MVC Concepts & MVC Architecture

MVC Component Role & Responsibility
Model C# class (Student.cs) defining data fields (Id, Name, Email, Course, Semester) and validation rules via Data Annotations.
View Razor files (.cshtml) generating user interface using HTML5, Bootstrap 5, and Razor Tag Helpers.
Controller StudentController.cs which processes incoming HTTP requests, binds form data, evaluates ModelState.IsValid, and determines the response.
Routing Configured in Program.cs as {controller=Home}/{action=Index}/{id?}.

5. Implementation Details & Key Code Snippets

A. Model with Data Annotations (Models/Student.cs)

public class Student
{
    public int Id { get; set; }

    [Required(ErrorMessage = "Student Name is required.")]
    [StringLength(60, MinimumLength = 3, ErrorMessage = "Name must be between 3 and 60 characters.")]
    [Display(Name = "Student Name")]
    public string Name { get; set; } = string.Empty;

    [Required(ErrorMessage = "Email Address is required.")]
    [EmailAddress(ErrorMessage = "Please enter a valid email address.")]
    [StringLength(100)]
    public string Email { get; set; } = string.Empty;

    [Required(ErrorMessage = "Course selection is required.")]
    public string Course { get; set; } = string.Empty;

    [Required(ErrorMessage = "Semester is required.")]
    [Range(1, 8, ErrorMessage = "Semester must be between 1 and 8.")]
    public int Semester { get; set; }

    public DateTime RegistrationDate { get; set; } = DateTime.Now;
}

B. Controller Action with Validation Enforcement (Controllers/StudentController.cs)

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Create(Student student)
{
    // Check validation rules
    if (!ModelState.IsValid)
    {
        ViewBag.Courses = AvailableCourses;
        return View(student); // Re-render form with error spans
    }

    // Persist valid registration to thread-safe list
    lock (_students)
    {
        student.Id = _students.Count > 0 ? _students.Max(s => s.Id) + 1 : 1;
        student.RegistrationDate = DateTime.Now;
        _students.Add(student);
    }

    TempData["SuccessMessage"] = $"Registration successful! {student.Name} has been enrolled.";
    return RedirectToAction(nameof(Index)); // POST-Redirect-GET pattern
}

7. Challenges Faced and Solutions

Challenge Technical Solution
Duplicate Submissions on Page Refresh Implemented the POST-Redirect-GET (PRG) pattern via RedirectToAction(nameof(Index)).
Form State Reset on Invalid Postback Repopulated ViewBag.Courses inside the invalid block before returning View(student).
Data Concurrency in Memory Implemented a lock (_students) block during ID generation and list insertion to guarantee thread safety.
